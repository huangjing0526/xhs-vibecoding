# 工作台的东西怎么归类

版本：v1.1
日期：2026-08-26
适用：`lib/capabilities.ts`、`lib/templates/`、侧栏与工具目录

这份文档只回答一个问题：**一样东西该放进哪个菜单**。改导航、加新区、加新工具之前先读它，别凭感觉塞。

---

## 1. 五类，一条判据切开

判据只有一条：**它在生产链里扮演什么角色**。一件东西只可能落一格。

| 类 | 唯一判据 | 装什么 |
|---|---|---|
| **素材** | 外面进来、还没变成任何东西的原料 | 开发日报里的真事、踩的坑、学到的做法；本地文档；选题池导入 |
| **模板** | 别人做成什么样 + 怎么做成的，可复刻的范例 | 出图模板、拆来的视频结构（节奏） |
| **资产** | 我的、会反复用的、复刻时填进模板槽位的东西 | 模特 / 产品 / 场景 |
| **作品** | 跑出来的产出 | 图片工厂的图、视频工厂的成片 |
| **项目** | 一次交付的容器，**自己不存内容**，只引用上面四者 | 一篇图文笔记；一条视频项目 |

### 模板的定义要更严一点

模板 = **样例 + 结构 + 槽位**，三件缺一不可：

- **样例**：它长什么样（成品图；节奏模板没有图，用节奏条代替）
- **结构**：它是怎么构成的（prompt + 视角 + 场景预设；或 hook + 分段 + 切镜表）
- **槽位**：要你补哪些自有素材（模特图/产品图；或选题 + 角色/产品/场景）

**没有槽位的东西不是模板，是作品。** 一张成品图只是结果，说不清"换成我的东西怎么做"。

---

## 2. 素材 / 资产 / 作品 凭什么分得开

这三个最容易混，因为都可能是图。真正的分界不在长相，在**它们各自存了什么**——因为回答的问题不同。

| | 数据结构 | 关键字段 | 回答什么 | 性质 |
|---|---|---|---|---|
| 素材 | `MaterialItem` | `event` `pitfall` `method` `status` | **讲什么** | 消耗品，提炼完就用掉了 |
| 资产 | `LibraryAssetEntry` | `name` `traits` | **用谁 / 用什么** | 常备品，有身份，反复出场 |
| 作品 | `WorkEntry` | `templateId` `provider` `model` `aspectRatio` `customPrompt` `createdAt` | **这一次怎么跑出来的** | 流水账，可溯源 |

### 三问，落一格

1. **它有名字和特征描述吗？** → 有 → **资产**
2. **它是机器跑出来、带着生成参数的吗？** → **作品**
3. **它是等着被提炼成选题的文字吗？** → **素材**

### 最锋利的那条边界：入册 = 命名

作品要变成资产，必须给**名字 + 特征描述**。这不是规定，是功能事实——没有 `traits` 的图喂给下一次生成锁不住脸也锁不住货，它在功能上当不了资产（见 `LIBRARY_COPY` 里每一种库的 `traitsHint`）。

**入册是给同一张图加身份，不是复制进第二个库。** 作品和资产永远不会存两份。

## 3. 两条硬规则（由代码把守，不靠人记）

### ① 名词区不进「工具」目录

`LIBRARY_AREAS = ["library", "templates", "assets", "works"]`，它们一律不带 `category`，因此永远不会出现在工具目录里。

这条**由类型强制**：`AREA_TABLE` 用 `satisfies Record<CategoryFreeAreaId, Omit<AreaDef, "category">> & …` 声明（`CategoryFreeAreaId = LibraryAreaId | NoteStepAreaId`），给 `assets` 补一个 `category` 会当场编译不过。导出的 `AREAS` 仍是统一的 `Record<AreaId, AreaDef>`，下游读 `category` 不用先分辨这是哪一类区。

> 侧栏把模板挪到了上段，但它依然在 `LIBRARY_AREAS` 里——**"是不是名词"和"摆在哪一段"是两回事**，前者管准入，后者由 `RAIL_GROUPS` 自己说了算。

同一手法也钉住了笔记步骤：`NOTE_STEP_AREAS = ["video", "rewrite", "quality"]` 一律不带 `category`——步骤住在项目详情页，不进目录（判据见第 4 节）。

### ② 一个区在首页最多露一次

不靠三张手写表恰好不相交，靠 `HOME_TOOL_AREAS` 从常量现算：把 `HOME_SCENES` 和 `HOME_FEATURED` 已经摆过的排掉，剩下的全部进小工具网格，只有一档。

## 4. 工具目录放什么

**只放不挑上下文、拿来就能用的动词。** 当前 7 个：

| 分区 | 工具 |
|---|---|
| 做图 | 图片工厂、叠字排版 |
| 做视频 | 视频工厂、视频去水印 |
| 沉淀模板 | 链接拆片、对标拆解 |
| 复盘 | 数据复盘 |

**流水线步骤不进目录。** 视频脚本、爆款优化、发布检查要先选中一个项目才能干活，它们是项目详情页里的步骤，不是平级工具——摆进目录只会让人点进去撞「先选一个项目」的空态。「谁是步骤」只看 `NOTE_STEP_AREAS` 这一张表；这条与规则①同一手法由类型钉死（步骤不许带 `category`），⌘K 仍能直达它们。

两点容易误判的：

- **链接拆片 / 对标拆解归「沉淀模板」**：它们跑出来的不是成品而是可复刻的结构，动词留在工具里，产出落进模板（名词）。模板页右上角的「拆一条」「拆博主」就是跳到这里。
- **图片工厂在工具里的角色是"不照模板、自己从头配"**。正常路径是「模板 → 照这个做」直接进工厂。所以「做图」这一区偏空是分类正确的副作用，不是漏了东西。

## 5. 侧栏三段

```
首页 · 模板 · 工具      从哪开工
───────────────────
素材 · 作品 · 资产      东西放哪
───────────────────
项目                    做给谁，收在最后
```

顺序即一条活的走法。`RAIL_GROUPS` 是唯一定义处，`RAIL_AREAS` 由它 `.flat()` 派生，窄屏顶栏跟着走。

---

## 6. 单向流转

```
素材 ──提炼──→ 项目
                 │
模板 ──照这个做──→ 工厂 ←── 资产（填进槽位）
                 │
                 ↓
               作品 ──入册（命名）──→ 资产
```

**不设反向入口。** 每个库只有一个出口动作：

| 库 | 出口动作 | 现状 |
|---|---|---|
| 素材 | 提炼成选题 | 已有（页头右上「生成选题」） |
| 模板 | 照这个做 | 已有（卡片悬停露出） |
| 作品 | 入册为资产 | 已有（大图里「存入资产库」） |
| 资产 | 用这位生成 | 已有（挂在具体那一位身上，带着她穿过模板目录进工厂，按槽位 id 落位） |

## 7. 模板是怎么做到"加一类只改两处"的

`lib/templates/index.ts` 是模板的单一事实源。出图模板和视频结构数据形状完全不同，靠一个判别联合抹平：

```ts
export type TemplateCard = ImageTemplateCard | RhythmTemplateCard;
export function templateTarget(card: TemplateCard): AreaId
```

目录页只管画卡片，工作台只管按 `card.kind` 分发，**谁都不用知道一共有几种模板**。

第三类（道库）就是按这个形状加进来的：`TemplateKind` 加一个字面量，这里加一个 `xxxTemplateCards()` 来源函数（见第 8 节）。目录页不用数有几种模板——「点了去哪」问 `templateTarget`，「图标配色打哪来」问 `templateOrigin`，两个函数都从 kind 派生。

### 派生，不要手写

节奏模板的槽位是 `["选题", ...CAST_SLOTS.map(s => s.label)]`。写这行时 `CAST_SLOTS` 只有角色和产品，后来加了场景——模板卡上的槽位自动跟上了。**凡是能从别处派生的，别在这里再写一遍。**

## 8. 道库是怎么变成第三类模板的

第 1 节的定义要求样例 + 结构 + 槽位，道库原先只有前两件——`BloggerDistillation` 九个字段全是「道」，
说不清「换成我的东西怎么做」。补齐的顺序是**先长槽位，再进目录**，反过来就是把定义弄松。

**① 槽位。** `slots: DaokuSlot[]` 是必填字段——造一条没槽位的道库当场编译不过，
和第 3 节两条硬规则同一手法：定义由类型把守，不靠人记。基座三槽（你的真事 / 读者痛点 / 可收藏资产）
由 `DAOKU_BASE_SLOTS` 派生不手写，蒸馏时按这位博主的道从 `DAOKU_EXTRA_SLOTS` 追加
（卡兹克要"主流工具名"、小A要"读者处境"）。**这是道库和另两类模板不一样的地方**：
出图模板和节奏模板的槽位对同类是齐平的，道库的不是——道不同，要补的料就不同。
槽位的 `source` 直接用 `AreaId`，取料口本来就是一个区，不另立一套名字。

**② 落盘。** 照节奏模板那套：`.local/daoku/<id>.json` 一条一个文件，`GET /api/daoku` 列目录即模板库。
id 按 bloggerId 定死，重蒸馏是覆盖同一份，不会在目录里堆出同一位博主的好几条。
「设为当前道库」和「存成模板」是同一个动作（`adoptDistillation`），只有这一处——
不落盘的道库只活在当前会话里，进不了模板目录，也就不算模板。

**③ 进目录。** 就是第 7 节说的形状：`TemplateKind` 加一个字面量，加一个 `daokuTemplateCards()` 来源函数。
路由与卡面不再靠目录页分辨 kind——`templateTarget`（点了去哪）和 `templateOrigin`（图标配色打哪来）
都从 kind 派生，目录页只问这两个函数。道库没有图也没有节奏条，样例是它的标题句式，卡面照着摆。

**「照这个做」为什么送去项目页**：道库约束的是「怎么写」，得先有一条选题才用得上。
它落在 `NOTE_STEP_AREAS` 里的「爆款优化」，直接跳会撞「先选一个项目」的空态——正是第 4 节清掉的那个毛病。
所以点它 = 设为当前道库 + 去项目页挑一条，提示条说清下一步。

**④ 蒸馏。** `POST /api/daoku/distill` 从样本蒸出道。模型只出「道」和额外槽位，
id / 名字 / 时间 / 基座三槽由服务端补——那几样编不得。额外槽位是**从 `DAOKU_EXTRA_SLOTS` 里挑 id**，
不许自拟：槽位的说法只有那一处，让模型自由造名字，同一个槽位下次就换了个叫法。
prompt 里复用 `DAOKU_PANBIELI`（判别力测）压住"解释一切的伪道"。
没配 AI 或模型返回不可用时，落到 `createFallbackBloggerDistillation` 那份关键词骨架，
并在界面上说明这版是骨架——空字段一律留骨架的，一次拉胯的返回掏不空整条道库。

### 还没做的

| 缺口 | 现状 | 影响 |
|---|---|---|
| 道库模板不能删 | `/api/daoku` 只有 GET / POST | 目录里的道库只能覆盖、不能清掉；等真堆多了再补，别提前造没人用的端点 |
| 样本还得手动粘 | `BloggerResearch` 的样本录入是手填，不抓平台数据 | 蒸馏质量吃样本的质量，样本少时模型只能按定位推断 |
