# AI 图片工厂 · 模板库说明

```
lib/imageFactory/index.ts              类型再导出 + 六个分类聚合成 BUILT_IN_IMAGE_TEMPLATES
lib/imageFactory/types.ts              类型 + 示意图下拉选项
lib/imageFactory/templates/*.ts        model / product / outfit / content / general
components/workflow/TemplateThumb.tsx  卡片示意图（内联 SVG）
.local/image-factory/samples/<模板id>/ 样例产出（不进 git）
```

`index.ts` 里的数组顺序决定分类标签与卡片的先后。引用路径仍是 `@/lib/imageFactory`，拆分前后不变。

## 界面流程

页面按「传图 → 选产出 → 生成」组织，不是「先挑模板」——用户手上先有的是图，
他想的是「给这张图做个白底图/细节图」。

```
左侧                                  右侧
① 上传素材   ← 页面第一眼，区域最大      生成什么（可多选，一次排队跑完）
② 想要什么画面（场景标签 + 补充要求）      · 小图点开看该产出的真实样例
③ 输出视图（按产出分组）   生成按钮 → 目标图（按产出分组）        生成引擎
                                     · 分类切换：模特资产 / 商品主图 / 详情图
                                       / 上身穿搭 / 内容配图 / 通用与自建
```

几条实现约定：

- **槽位取并集**：三个电商产出都只要一张商品图，就只让用户传一次；某个槽位只要有一个
  产出要求必传，它就是必传
- **每个任务带自己的 key**（`<模板id>` 或 `<模板id>__<视图id>`）当后端产物子目录名，
  多产出同跑不会互相覆盖；参考图按「一次运行」只存一份
- **画面场景跟着焦点产出走**：多选时不可能同时摊开所有产出的场景标签，显示最后勾选的
  那个，标题里写明来自哪个产出
- **未记录过视图勾选的产出视为全选**，省掉一次初始化

## 三层结构

```
L1 分类 category    模特资产 / 商品主图 / 详情图 / 上身穿搭 / 内容配图 / 通用与自建
L2 模板 template    规则骨架 + 槽位 slots + 视角 views
L3 场景预设 scenePresets   一句话画面描述，点选后写进「补充生成要求」
                    预设多的模板再按 group 分档（上身场景图的 51 条分了四组）
```

**分类只按一个判据划，同一层不混维度。** 早先的「电商 / 服装 / 小红书 / 创意」把渠道、
品类、资产、兜底四个维度并排放，必然重叠——服装三视图挂在电商下、平铺变模特图挂在服装下，
两边都对也都不对。现在的判据是：

| 分类 | 判据 |
|---|---|
| 模特资产 | 有人、无货（穿的是固定基础款） |
| 商品主图 | 无人，交付到平台主图位的规范展示 |
| 详情图 | 无人，交付到详情页的场景氛围与局部特写 |
| 上身穿搭 | 人 + 要卖的那件货 |
| 内容配图 | 去向是笔记 / 封面 / 视频，不进商详页 |
| 通用与自建 | 不绑定主体也不绑定坑位；自建模板默认落这里 |

两处容易藏的重叠，判据里写死了：**笔记实拍配图 vs 商品场景图**分界在质感与坑位
（手机随手拍进笔记 / 商业棚拍进商详），不在画面里有什么；**服装挂拍图**即使选了店内
场景预设仍归主图位，按坑位分不按背景分。

## 产出归哪个库

分类回答「这张图交付到哪个坑位」，`producesAsset` 回答「这张图值不值得留着反复用」，
两者不是一回事——所以它是模板上的独立字段，不跟着分类走。填了的模板，结果区才出
「整组存入 X 库」，没填的产出跑完就跑完了。

| producesAsset | 模板 | 为什么是可复用资产 |
|---|---|---|
| `models` | 模特资产图、模特姿势拓展 | 一次做齐一套角度，之后每条内容都拿同一个人 |
| `products` | 电商白底图、服装三视图 | 干净多视角，是后续锁住同一件货的参考 |
| `scenes` | 商品场景图、上身场景图 | 可复用的不是那件货，是那套环境与光线 |

三个库的存法、增删、入库校验完全一样，按 kind 参数化（`lib/imageFactory/libraries.ts`
是唯一那张文案表）。入库有两条路：跑完存产物路径，或直接上传手上已有的图——自己拍的
门店与商品实拍从没跑过生成，只留前一条路它们永远进不来。

**模板层只放规则，场景全部下沉到 L3。** 这样换场景不会把「保持什么、禁止什么」冲掉，
也不用为每个场景开一个模板。UI 上场景是单选，选中态由输入框内容反推——手改一个字就自动脱离选中。

## 模板 prompt 的六段骨架

新增模板照这个顺序写，缺一段就会在产出里暴露：

1. **任务一句话** —— 生成一张什么图
2. **必须保持** —— 人物：脸/发型/肤色/体型；商品：外形/颜色/材质/五金/做工
3. **默认值** —— 没传人物参考图时的兜底人种（不写就会出欧美脸，见下方踩坑）
4. **场景与光线** —— 光影方向要和人物、和季节自洽
5. **禁止项** —— 文字、水印、品牌标识、促销标签、臆造部件、多视角拼图
6. **输出要求** —— 真实可发布、单张、构图留白

场景预设只写第 4 段里的场景部分，30-60 字，**不要写具体服装**（服装由参考图决定，
预设里再写「粉色羽绒服」只会和参考图打架）。

### 上身场景图是四个模板合并来的

`对镜自拍` / `门店场景` / `户外街拍` / `人像写真` 曾是四个独立模板，但它们的槽位完全相同、
prompt 骨架逐句相同，真正的差异全在场景预设里——那不是四个模板，是一个模板的四组场景。
合并后 51 条预设按 `group` 分成 **镜面自拍 12 / 门店室内 13 / 户外街道 13 / 写真氛围 13**，
四张原卡片预览图降级成分组封面继续用（每组第一条预设的 `preview` 即该组封面）。

场景多到一屏铺不下时就该这么做：**开新模板的前提是规则不同，只有画面不同就加预设。**

## 边界（别让模板互相打架）

- **封面排版**走 `CoverStudio` + `lib/cover.ts`，图片工厂不做排版
- **流程图/清单图**走 `imageWorkflow` 的 SVG 渲染，图片工厂只做实拍感照片
- **品牌视觉包**只出底图，叠字仍归封面模块
- **只有画面不同不开新模板**：同槽位同规则的场景变体一律进 `scenePresets`，预设过多再分 `group`

## 踩过的坑

- **不写人种就出欧美脸**：模板 prompt 只写「提供模特参考图时保持该模特的脸」，
  没写不提供时的兜底，codex 连续三张给欧美面孔。凡可能出现人物或手部的模板，
  都要在第 3 段写明默认值。
- **门店场景要禁店招文字**：原始素材里有真实店招（如「糖糖家」），直接生成有侵权风险。
  户外街拍同理要禁车牌。
- **对比图不能做效果对比**：只换场景与光线，禁止暗示功效、前后改善。

## 场景预设的素材来源

## 卡片预览图

模板卡上是这个模板**真实跑出来的产出**，不是示意图——挑模板时看效果比看图标直观。

```
.local/image-factory/samples/<模板id>/*.png   原图（不进 git，本机跑出来的）
public/template-previews/<模板id>.jpg          卡片预览（进 git，600×750）
public/template-previews/<模板id>__<视角id>.jpg 视角缩略图（400×400）；两者合计约 1 MB
lib/imageFactory/templates/*.ts                模板的 preview 字段指向它
```

**多视角的产出，每个视角也要有样例**——卡片上写「4 视图」说不清每个视角拍成什么样。
视角缩略图是方的（400×400），文件名约定为 `<视角id>.png`，同一产出的几个视角
**必须用同一件商品**，用户看到的才是「同一个东西的四个视角」。

换样例或加模板后重出预览图：

```bash
node scripts/image-factory/build-previews.mjs                          # 各模板用目录里第一张
node scripts/image-factory/build-previews.mjs --pick <id>=<文件名>      # 指定模板卡用哪张
node scripts/image-factory/build-previews.mjs --view <id>:<视角id>=<文件名>  # 指定视角缩略图
```

卡片图区是 `aspect-[4/5]`，脚本按 4:5 裁切、纵向偏上 18%（人像模板保住脸和上半身）。
没有 preview 的模板（自建的）回落到 `TemplateThumb` 的内联 SVG 示意图。

同一分类里**别用同一件商品**，否则几张卡长得一样、等于没有预览。电商那几个分别用了
深蓝长裙 / 红花印花 / 薄荷绿百褶 / 白蕾丝，顺带也验证了模板对印花、褶皱、蕾丝的保持能力。

## 样例产出

每个模板至少留一张真机跑出来的样例，路径 `.local/image-factory/samples/<模板id>/<预设或视角>.png`
（不进 git）。改版前 20 个模板全覆盖，共 19 张；合并掉的四个模板样例仍留在原目录里对照。改了模板 prompt 之后重跑一张对照，
比读 prompt 更快判断有没有改坏。

`flat-to-model/rainy-cafe-旧prompt-欧美脸.png` 是故意留的反例，对照 `winter-snow-修复后.png`
就能看出「写不写默认人种」的差别。

## 已知限制

- gemini CLI 被硬拦（`generate/route.ts` 里个人订阅登录被拒），只能用 codex / grok
- 自建模板仍存 localStorage，换设备会丢（内置模板走代码库，不受影响）
- 自建模板的编辑器已能配名称、分类、比例、示意图、生成规则、槽位（含必传开关）、输出视图、画面场景
